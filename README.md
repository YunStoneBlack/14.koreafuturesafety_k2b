# 한국미래안전 K2B 서류 자동제출 프로그램

12-1 프로젝트(`(주)한국미래안전 보고서 작성 자동화 프로그램 hwpx버전`)에서 생성된 기술지도
결과보고서(hwpx/PDF)의 내용을 안전보건공단 K2B 시스템(https://k2b.kosha.or.kr/)의
"재해예방기관 기술지도" 화면에 자동으로 입력/첨부하는 프로그램.

## 개발 단계 안내 (중요)

**최종 "저장"(=제출) 버튼 클릭은 아직 구현하지 않는다.** 실수로 실제 정부 시스템에
잘못된 데이터가 제출되는 걸 막기 위해, 완성본이 나오기 전까지는 폼 입력/사진 첨부까지만
자동화하고 사람이 화면을 직접 보고 마지막 저장 버튼을 누른다. 자동 제출 기능은 다른
모든 기능이 검증된 뒤 맨 마지막에 추가한다.

## 아키텍처 방향

- 브라우저 자동화: Playwright의 자체 Chromium (CDP로 기존 크롬에 붙는 방식 아님) —
  로컬 개발 중엔 headed로 눈으로 확인, 추후 AWS 서버 이식 시 headless로 동일 코드 사용 가능.
- 로그인 정보: `core/credentials.py` — Windows Credential Manager(keyring)에 암호화 저장.
  대화창/코드에 평문으로 남기지 않는다.
- 데이터 소스: 최종적으로는 12-1 프로젝트의 `app.db`(SQLite, `Report`/`Site` 테이블)를
  읽어서 K2B 폼 필드에 매핑한다. 단, 12-1이 아직 실전 투입 전이라 현재 DB는 테스트
  데이터뿐 — 로직 검증은 테스트 데이터로 먼저 진행.
- 향후 이식 목표: 13번 프로젝트(그룹웨어, Spring Boot, AWS)에서 폰으로 "K2B 제출" 버튼을
  누르면 서버에 내부 Python API(FastAPI 등)가 이 자동화 로직을 headless로 실행하는 구조.

## K2B 화면 흐름 (PPT 스크린샷 기반 파악)

1. 로그인 (ID/PASSWORD)
2. 나의업무 > 건설재해예방전문지도기관 기술지도지원 > 재해예방기관 기술지도
3. 검색조건에 현장명 입력 → 조회 → 결과 행 체크 → 상세보기 → "재해예방기술지도 등록" 모달
4. 기술지도 탭 → 차수 추가 → 필드 입력:
   - 기술지도일, 지도기관명(고정), 점검자, 현장책임자명/연락처, 공정률, 지도건수,
     교육인원, 배포자료건수, 현재 작업공정, 특이사항
   - 경영책임자/건설업체 본사 통보일(분기), 비계사용현황(+비계종류)
   - 현장책임자 등 통보방법(직접전달/등기우편/전자우편/모바일/기타)
   - 이전 기술지도 이행여부(이행/불이행/해당없음), 건설공사 발주자 통보일자
5. 불량사업장 통보 — 해당 시에만 별도 처리 (기본은 미해당)
6. 대형사고 위험작업 — 해당없음 체크 또는 개별 선택 필요
7. 사진 첨부: 현장전경 사진 / 현장점검 사진 / 현장개선 사진 (각각 "사진첨부" 버튼, 다중 파일)
8. **저장 버튼 클릭 = 실제 제출** → 지금은 여기서 멈추고 사람이 확인 후 수동 클릭

## 셀렉터 확보 방법

실제 화면 DOM에 접근할 수 없어서, `record_flow.py`로 Playwright codegen을 띄워
사람이 한 번 직접 로그인 → 화면 이동 → 필드 입력까지(저장 버튼 누르기 전까지) 진행하면
`data/recorded_flow.py`에 실제 셀렉터가 담긴 코드가 자동 생성된다.

```bash
venv/Scripts/python.exe record_flow.py
```

## 설치

```bash
python -m venv venv
venv/Scripts/python.exe -m pip install -r requirements.txt
venv/Scripts/python.exe -m playwright install chromium
```

## 로그인 정보 저장

```bash
venv/Scripts/python.exe -m core.credentials set
```

## 배포(담당요원 PC) — 폴더 배치 규칙 (중요, 2026-09-17 확정)

담당요원 각자 PC에서 "12-1(보고서 작성) → 14(K2B 제출)"를 한 흐름으로 쓰는 게 목표라,
**두 exe를 반드시 같은 상위 폴더 밑에 나란히 설치**해야 한다:

```
아무 상위 폴더\
  한국미래안전_기술지도결과보고서\   ← 12-1 dist 폴더 그대로
  한국미래안전_K2B자동제출\          ← 14 dist 폴더 그대로
```

`core/config.py`가 frozen(exe) 상태에서 자기 폴더의 부모 밑에 위 12-1 폴더 이름이
있는지 찾아 그 안의 실제 `data/app.db`를 사용한다(폴더 이름이 12-1
`packaging/build_exe.py`의 `APP_NAME`과 정확히 일치해야 함). 이 폴더를 못 찾으면
exe에 번들된 데모 DB(`packaging/build_demo_data.py`로 생성)로 대체된다 — 12-1 없이
14만 영업용으로 보여줄 때를 위한 fallback이다.
